# VinDr-PCXR lokal auswerten – sechs Schritte

1. **Python installieren.** [Python 3.12](https://www.python.org/downloads/) in 64 Bit installieren; unter Windows „Add Python to PATH“ aktivieren. Unterstützte Anleitung: Windows x64 und Mac mit Apple-Chip. Für alte Intel-Macs fehlen passende aktuelle PyTorch-Pakete; diese Kombination ist nicht geprüft. Etwa 10 GB freien Platz und möglichst 8 GB RAM vorsehen.

2. **Repository herunterladen.** Auf [GitHub](https://github.com/paploooov/medical-ai-reliability-lab) „Code → Download ZIP“, entpacken, Terminal/PowerShell im entpackten Projektordner öffnen. Dort müssen `scripts/`, `configs/` und die 30 `.pt`-Dateien in `reports/original_512/thoraxis_30/checkpoints/` liegen. Daten und Projekt in lokalen Ordnern außerhalb von OneDrive/iCloud/Dropbox speichern.

3. **Abhängigkeiten installieren.** Windows: `py -3.12 -m venv .venv-vindr`, dann `.\.venv-vindr\Scripts\python.exe -m pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cpu`, dann `.\.venv-vindr\Scripts\python.exe -m pip install -r requirements-vindr-local.txt`. Mac: `python3.12 -m venv .venv-vindr`, dann `.venv-vindr/bin/python -m pip install -r requirements-vindr-local.txt`. Danach **vor dem echten Lauf den Selbsttest ausführen**: Windows `.\.venv-vindr\Scripts\python.exe scripts/run_vindr_external.py --selftest`; Mac `.venv-vindr/bin/python scripts/run_vindr_external.py --selftest`. Er prüft Installation, alle 30 Checkpoint-Hashes und synthetische DICOMs (8/12/16 Bit, MONOCHROME1, Fensterung und 512px-Pipeline), ohne echte Daten. Erst bei „Selbsttest bestanden“ fortfahren. Die Auswertung braucht danach kein Internet und lädt keine Gewichte nach.

4. **Nur Testdaten lokal herunterladen.** Bei [PhysioNet, VinDr-PCXR 1.0.0](https://physionet.org/content/vindr-pcxr/1.0.0/) Zugangsvoraussetzungen erfüllen und DUA akzeptieren. Im Projektordner einen dieser Befehle ausführen; den Zielpfad ersetzen:

   Windows (PowerShell):
   ```powershell
   .\.venv-vindr\Scripts\python.exe scripts/download_vindr_test.py --data-dir "C:\lokale_daten\vindr-pcxr"
   ```
   Mac (Terminal):
   ```bash
   .venv-vindr/bin/python scripts/download_vindr_test.py --data-dir "/Users/DEINNAME/lokale_daten/vindr-pcxr"
   ```
   Benutzername und Passwort erst in den lokalen Abfragen eingeben, niemals hier im Chat oder als Befehlsargument. Das Passwort wird verdeckt eingegeben, nicht gespeichert und nur zur Anmeldung über HTTPS an PhysioNet gesendet. Das Skript lädt ausschließlich `test/` (1.397 DICOMs, veröffentlicht etwa 5,7 GB) und `image_labels_test.csv`, nebeneinander in den Zielordner. Bei Unterbrechung denselben Befehl erneut ausführen: `.part`-Dateien werden fortgesetzt, vollständige Dateien übersprungen. Falls der Server keine Fortsetzung unterstützt, beginnt nur die angefangene Datei neu. Keine Trainingsbilder oder Bounding-Box-Dateien werden geladen. Dateien und Namen bleiben lokal; die Fortschrittsanzeige nennt nur Anzahlen. Bei `D1` Zugang/DUA, Verbindung und Speicherplatz lokal prüfen. Keine Daten oder Screenshots davon senden.

5. **Einmal starten.** Windows: `.\.venv-vindr\Scripts\python.exe scripts/run_vindr_external.py --data-dir "C:\lokale_daten\vindr-pcxr" --out ergebnis.json`. Mac: `.venv-vindr/bin/python scripts/run_vindr_external.py --data-dir "/Users/DEINNAME/lokale_daten/vindr-pcxr" --out ergebnis.json`. Den Datenpfad ersetzen. Netzwerk kann getrennt werden. Bestehende Ergebnisdateien werden nicht überschrieben. Während des Laufs gibt es bewusst keine Bildnamen oder Einzelbild-Logs. Grob **10–30 Minuten auf einem normalen Laptop**, bei langsamer CPU/Datenträger länger. Herleitung: Hier benötigten vier künstliche Bilder durch alle 30 Modelle 0,615 Sekunden (ein CPU-Thread); das entspricht etwa 3,6 Minuten reiner Modellrechnung für 1.397 Bilder, ohne DICOM-Laden und Bootstrap. Kein gemessener VinDr-Lauf.

6. **Nur `ergebnis.json` zurückgeben.** Sie enthält zusammengefasste Fallzahlen und Modellkennzahlen, die 5×5-Kontraste, getrennte Seed-/Split-Streuung, Gruppen-Bootstrap-Intervalle und Modell-Hashes. Bilder, Labeldateien, IDs und Einzelvorhersagen werden nicht exportiert. Die JSON hält zusätzlich die Pillow-Version fest. Bei Abbruch nur den Fehlercode weitergeben: **E1** Installation, **E2** Labeldatei/Schema, **E3** Bildanzahl/Zuordnung, **E4** DICOM-Format, **E5** Checkpoint/Hash, **E6** Ausgabepfad, **E7** Berechnung, **E8** Aufruf. Die Meldungen enthalten keine Pfade, IDs oder Datenwerte. Modelle, Schwellen oder Regeln nicht nachträglich anpassen und nicht mit anderen Varianten erneut auswerten.

**Stand und Grenzen:** [Protokoll](THORAXIS_VINDR_PROTOKOLL.md), [Labels und Regeln](../configs/thoraxis_vindr_external.json) sowie die Bildverarbeitung bleiben unverändert. 16 synthetische Tests bestanden, einschließlich Selbsttest, Fehlercodes, Pillow-Ausgabe, Download-Fortsetzung und Zugriffsbeschränkung auf den Testteil. Kein echter PhysioNet-Download wurde hier ausgeführt; der Download ist mit simulierten Serverantworten geprüft. Tests liefen unter Linux, Windows/Mac wurden hier nicht praktisch geprüft. Fehlende Patientenverknüpfung begrenzt weiterhin die Unsicherheitsaussage.
